01

The problem

A content team can’t manually review every page equally. FlyRank’s teams already use a simple, transparent rule to flag review candidates: if a page hasn’t been updated in a while and still gets meaningful search visibility, flag it. That rule is easy to trust because it’s easy to read — but it was never checked against an actual outcome. This project asks a narrow, checkable question:

Can an interpretable machine-learning model rank pages by observed decline risk more usefully than the existing rule — when both are scored against the same target, on the same rows, the same way?

The unit of analysis is one pseudonymized content page. The output is a ranked queue with a reason code a reviewer can read and check. A false positive costs review time on a page that didn’t need it; a false negative can leave a genuinely declining page unreviewed — so ranking quality near the top of the queue matters more than raw accuracy.

02

Data

This uses the anonymized FlyRank ML Internship starter slice: 30,000 pseudonymized content pages across 32 pseudonymized clients, with observed search and engagement metrics, content metadata, and freshness fields — no external access was needed.

The model’s features are an allowlist already defined once, in the repo’s shared reference code (scripts/ml_utils.py): 18 numeric fields (visibility, engagement, freshness, content properties) and 8 categorical fields. Two fields are deliberately excluded because they define the label (trend_direction, trend_pct); the pseudonymous IDs are used only to group rows for validation, never as inputs.

no client names no domains no URLs no raw queries IDs: grouping only
03

The baseline

FlyRank’s existing rule, built and checked for leakage in an earlier assignment: a page is stale when it hasn’t been updated in 180+ days, and visible when it still has any measured search impressions. Together, stale + visible → REFRESH_REVIEW. It flags 174 of the 30,000 pages (0.58%) — deliberately conservative, and fully explainable in one sentence.

One honest note: on this particular slice, every page already has at least one measured impression by construction, so the “visible” half of the rule never actually excludes anything here — in practice it reduces to the staleness threshold alone on this dataset. That’s a property of the data, not a flaw in the rule.

04

Method

A regularized logistic regression (balanced class weights, fixed seed) — deliberately not a decision tree or random forest. The goal here is a ranking model a reviewer can audit, not the strongest possible score; logistic regression is the smallest model that’s technically defensible for a yes/no observed label, and its coefficients read directly as “which signals push the score up or down.”

The target is is_declining_label = (trend_direction == "down") — the same definition used throughout the underlying dataset’s documentation, comparing a page’s most recent 30-day search impressions against the 30 days before that.

05

Evaluation — and the split that had to change

The first attempt used a standard single 80/20 split grouped by client (so no client’s pages leak between train and test). It failed in an instructive way: the 174 baseline-flagged pages are concentrated in only 10 of 32 clients, and that first random split happened to put zero of those clients in the test set. The baseline’s test-set ROC-AUC came out as a meaningless 0.5 — not because the rule is bad, but because the test set literally contained no example of it firing.

The fix: grouped 5-fold cross-validation by client, with every metric computed on concatenated out-of-fold predictions across all 30,000 rows. Every client — and therefore every baseline-flagged page — ends up in exactly one out-of-fold evaluation. This is the smallest defensible correction, not a search for a friendlier split.

Read this plainly: the baseline’s ROC-AUC (0.499) is indistinguishable from chance, and its average precision (0.542) sits exactly at the base rate — it carries no measurable signal for this label. That’s confirmed independently: among the 174 pages the rule flags, the actual decline rate is 47.1%, slightly below the 54.2% overall rate. The rule was built to answer “is this page stale and still visible?” — not “is this page’s traffic declining right now?” This is the first time the two questions have been measured against each other, and they turn out to be only weakly related. That is a real result, kept as reported, not reframed to look better.

Error analysis (out-of-fold scores, 0.5 threshold): 18,857 correct, 6,729 false positives, 4,414 false negatives — recall 0.729, precision 0.638. False negatives are the costlier error here (a declining page slips through unreviewed); 0.5 is a default threshold, not one tuned against real reviewer capacity.

06

What the model leans on

Reading the largest coefficients directionally, never causally: higher recent visibility is associated with a higher predicted decline probability, while landing in the top-3 search position bucket or the “excellent” visibility bucket is associated with a lower one — already-strong pages read as more stable. Higher recent clicks read as protective. This is a plausible, checkable pattern, and nothing in the coefficient list has the near-perfect, single-feature-dominates signature that would suggest the model is quietly reading the answer.

  4. Re-run the ranking when the data window changes materially.
08

Limitations & honest framing

  • Starter slice, not the full warehouse. 30,000 rows / 32 clients is a teaching slice of FlyRank’s much larger dataset; treat these as slice-level findings.
  • Baseline and model measure different constructs. Their weak relationship is a finding about fit to this label, not a verdict on the rule’s original purpose.
  • Cross-sectional label, not a forecast. The decline label compares two trailing 30-day windows in one snapshot — an observed pattern, not a validated future outcome.
  • Untuned threshold. 0.5 is a default, not tuned to real reviewer capacity or cost asymmetry.
  • Grouped CV, not a time-based holdout. Folds test generalization across clients, not across time — a single-snapshot dataset doesn’t support a genuine time split.
  • No causal claims, anywhere. This does not claim any feature causes decline, that refreshing a page improves performance, or that it models Google’s ranking algorithm.
